Actúa como un equipo full-stack senior + ops. Construye en Next.js un **Marketplace multi-vendedor** para cuidado personal con el slogan:
“Rutina simple, piel en calma”.

## Objetivos del MVP
1) Catálogo multi-vendedor con precios **en COP mostrando “IVA incl.” (19%)**, variantes, stock y reseñas.
2) Onboarding de vendedores con KYC básico, creación de tienda, CRUD de productos (imágenes, precio base + IVA), pedidos, y dashboard de comisiones/payouts.
3) **Split payments** con Stripe Connect (test) + webhook. Base (stubs) para Mercado Pago Split.
4) **Recomendador** `/api/recommend` con quiz (zona, sensibilidad, gym, vive_solo, cabello_largo, presupuesto) y re-ranking por performance del vendedor.
5) **Ranker de vendedores** configurable por JSON (pesos y normalización), con modo debug (solo admin) y trazabilidad de decisiones.
6) Carrito multi-vendedor con checkout único: subtotales por vendedor, **IVA** desglosado, comisión marketplace transparente, y costos de envío por perfil.
7) Blog en MDX + CMS ligero; **disclaimer médico persistente** (“cuidado personal, no consejo ni diagnóstico”).
8) **Bucle conversacional** de 7 días (stubs email/WhatsApp): tips, adherencia, fotos antes/después (opt-in), feedback.
9) Panel Admin: aprobar/suspender vendedores, moderar listados, gestionar comisiones, KPIs (GMV, take rate, fill-rate, P95 despacho), proveedores/RFP/SLA.
10) **Endurecimiento**: rate-limit en APIs críticas, auditoría de cambios (ranker/comisiones), moderación de claims (bloqueo de lenguaje médico), políticas de devolución por vendedor.
11) SEO/Accesibilidad: schema Product/AggregateRating, alt text, contraste AA, títulos/meta. Preparado para multi-moneda vía comentarios.

## Stack
- Next.js (App Router) + TypeScript + Tailwind.
- Auth: NextAuth (Email/Password + Google OAuth) con roles: user | vendor | admin.
- DB: Prisma + SQLite (Replit). Comentarios para migrar a Postgres/Supabase.
- Pagos: Stripe Connect (Standard/Express, test) + webhook.
- Contenido: MDX para blog.
- Estado: Server Actions/React Query.
- Moneda: COP, formato “$59.900 COP **IVA incl.**”.

## Reglas del recomendador (rules.ts)
- Si `zona==='espalda' && vive_solo` => top_pick = “Kit Bacne”.
- Si `cabello_largo` => top_pick o add-on “Ducha-Orden™”.
- Si `gym` => add-on pads bolsillo (placeholder).
- Si `sensibilidad==='alta'` => variant “Sensitive” (evita activos fuertes).
- Re-ordenar candidatos por **ranker** (SLA, ETA, rating, NPS, devoluciones, on-time, respuesta, stock, comisión, distancia, sensitiveOk).
- Respuesta incluye:
```

{
segmento, top_pick, add_ons, variant, rationale,
vendorSuggestion: { vendorId, score, reason[], breakdown? (solo admin) }
}

```

## Ranker configurable
- Archivo `/lib/ranker.config.json` con:
- `weights`: slaP95Dispatch(0.22), deliveryEta(0.15), ratingAvg(0.18), nps(0.08), returnRate(0.10), onTimeShipRate(0.10), supportResponseHrs(0.05), stockHealth(0.04), takeRateBp(0.02), distanceKm(0.03), sensitiveOk(0.03)
- `thresholds`: minRating=3.8, maxSlaP95Hours=96, maxReturnRate=0.08
- `boosts`: badgeSensitiveOk=0.02, localVendor=0.03 (dist<30), fastTrack=0.02 (ETA<=2)
- `penalties`: policyStrike=0.10, lateShipStrike=0.05 (onTime<0.85)
- `tieBreakers`: ["deliveryEta","ratingAvg","distanceKm","priceFinal"]
- `ranker.ts` implementa normalizaciones (0..1), aplica pesos, boosts/penalties y **hard filters** (rating<threshold, SLA>max, returns>max).
- Modo debug (admin) con `<DebugRank />` y almacenamiento de `rankingMeta` en Recommendation.

## Endurecimiento
- **Rate-limit** en `/api/checkout`, `/api/recommend`, `/api/reviews`, `/api/suggestions` (token bucket en memoria).
- **Audit log**: eventos “RANKER_UPDATE”, “COMMISSION_UPDATE”, “VENDOR_STATUS”, “PRODUCT_MOD” (con actor, target, payload).
- **Moderación de claims**: bloquear palabras (“cura”, “diagnóstico”, “tratamiento médico”, etc.) y reemplazos (“cuidado personal”). En POST/PATCH de producto, fallar con 400 si hay claim prohibido.
- **Política de devoluciones por vendedor**: campo `Vendor.returnPolicy` renderizado en PDP y link en checkout. Botón “Iniciar devolución” en pedidos (stub ticketing/email).
